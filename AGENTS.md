# AGENTS.md

- Test command: `npm ci && npm test` (builds `dist/`, then runs every test; CI runs the same).
- **The published script runs the queue live** (owner decision): `src/chatgpt/queue/live-dispatcher.js` fills the real composer and clicks Send/Stop through the adapter's selectors, and, with `src/chatgpt/recovery.js`, is one of the only two files in `src/` allowed to `.click()` (the recovery's single click is ChatGPT's own "Try again" control inside its conversation-load failure card: at most 3 attempts per conversation and route visit, never while the owner types, never a reload or a send; `tests/platform.test.js` enforces it). `config.dryRun` is an opt-in for testing that swaps in the no-side-effect dispatcher. **You never send anything live yourself:** tests and local validation use DOM fixtures in `tests/fixtures/` only; never load chatgpt.com, send a prompt, or click native Send/Stop from a test or script. A banned-primitive test blocks `fetch`, `XMLHttpRequest`, `requestSubmit` and `.click()` outside the live dispatcher. Live ChatGPT tests need the owner's approved budget (#625) and run outside this repo's CI.
- Gate command: `npm run gate` (rebuilds, then runs `tests/gate/*.gate.js` against the bundled script and writes `build/gate-report.json`). It is the acceptance gate for #631 (fixtures and fault injection only, no live traffic); CI runs it. Never weaken or skip a gate case; a failing case blocks any live test.
- Profiling: `docs/profiling.md`. `profiling/measure.js` must stay read-only (a test scans it); run it against real threads only as that document says.
- Commit `dist/` with every source change (`npm run build`); CI fails on a stale `dist/`. Bump the version with `npm run bump -- <id> <patch|minor|major>`; managers ignore non-increasing versions.
- The queue (#630) is ONE accumulating pending prompt per account + conversation (`src/chatgpt/queue/`), entered and edited only in ChatGPT's native composer: while a response runs, plain Enter appends with one blank line, there is no second input, no rows and no overflow menu. Waiting for the response or for Send is never an attempt and nothing is retried; a send claims an immutable in-flight snapshot. The Enter/submit/click interception lives only in `controller.js`; tests assert the card has no `textarea`/`input`.
- ResizeObserver is allowed only in `src/chatgpt/virtualization/backend.js` (active turn elements only); everything else observes through the hub.
- Startup is `src/core/boot.js`: it waits (one bounded observer, visible give-up) for the layout, restarts on route changes and root replacement, and a composer without turns (new chat) runs composer-only. Never add a one-shot layout check at script start.
- **One right-side pane** (#628): `src/chatgpt/rail/rail.js` adds the minimap-over-prompt-list sections to ChatGPT's own summary pane (found structurally by `adapter.nativeSummary`; nothing native is moved, removed or re-created, the Outputs section only gets our `data-gs-*` attributes and a disclosure button) and shows one docked fallback pane only while no native pane is mounted. Never add a second panel, card shell, fixed colors or floating overlay; styling uses ChatGPT's tokens only (a test blocks literal colors). The pane's page-layout reservation is written only by `src/chatgpt/rail/rail-layout.js` (the `data-gs-column` padding on the page column found by `adapter.column`); it reserves only what still overlaps the pane (nothing when the native pane already takes its width), is change-only and is removed on dispose. Per-conversation pane state lives in `rail-state.js` (in memory) and `createPanePrefs` (collapse booleans only, in `localStorage`) and never crosses conversation ids (tests/rail-layout.test.js, tests/native-pane.test.js, tests/gate/rail.gate.js). The script never clicks the native summary toggle (only the live dispatcher may `.click()`).
- The only automatic scroll is the one on opening a conversation (`runtime.open` -> `scroll.mayOpen()`, the start of the latest prompt to the top of the viewport; yields to any user scroll, never repeats). All scroll writes go through `src/core/scroll-manager.js`; all DOM observation through `src/core/observers.js`; all ChatGPT selectors live in `src/chatgpt/adapter.js`.
- Public repository: no private data, profile paths, account names, tokens or personal identifiers anywhere (code, fixtures, commits, issues).
- Keep `@grant none` unless a review justifies a grant.
