# AGENTS.md

- Test command: `npm ci && npm test` (builds `dist/`, then runs every test; CI runs the same).
- **The published script runs the queue live** (owner decision): `src/chatgpt/queue/live-dispatcher.js` fills the real composer and clicks Send/Stop through the adapter's selectors, and, with `src/chatgpt/recovery.js` and `src/chatgpt/thinking.js`, is one of the only three files in `src/` allowed to `.click()` (the recovery's single click is ChatGPT's own "Try again" control inside its conversation-load failure card: at most 3 attempts per conversation and route visit, never while the owner types, never a reload or a send; the thinking expander's single click is the disclosure button of a collapsed thinking trace inside a conversation turn, found by `adapter.thinkingToggles`, once per trace and visit, only while it is in view, never Send/Stop or anything in the composer; `tests/platform.test.js` enforces both). `config.dryRun` is an opt-in for testing that swaps in the no-side-effect dispatcher. **You never send anything live yourself:** tests and local validation use DOM fixtures in `tests/fixtures/` only; never load chatgpt.com, send a prompt, or click native Send/Stop from a test or script. A banned-primitive test blocks `fetch`, `XMLHttpRequest`, `requestSubmit` and `.click()` outside the live dispatcher. Live ChatGPT tests need the owner's approved budget (#625) and run outside this repo's CI.
- Gate command: `npm run gate` (rebuilds, then runs `tests/gate/*.gate.js` against the bundled script and writes `build/gate-report.json`). It is the acceptance gate for #631 (fixtures and fault injection only, no live traffic); CI runs it. Never weaken or skip a gate case; a failing case blocks any live test.
- Profiling: `docs/profiling.md`. `profiling/measure.js` must stay read-only (a test scans it); run it against real threads only as that document says.
- Commit `dist/` with every source change (`npm run build`); CI fails on a stale `dist/`. **Agents never edit versions**: add an entry under `## Unreleased` in `CHANGELOG.md` for every change that ships (`src/`, `dist/`, `manifest.json`) and put a standalone `Release: minor` or `Release: major` line in that section only when a larger bump is warranted (patch is the default). `scripts/check-pr.mjs` (CI) refuses edits to `manifest.json` versions, `@version` in `dist/`, release sections in the changelog, and a shipping change with no new entry; after the merge `scripts/release.mjs` (`.github/workflows/release.yml`) derives the version, rebuilds `dist/` and commits the release. Managers ignore non-increasing versions, so a rollback is a revert plus a new changelog entry.
- The queue (#630) is ONE accumulating pending prompt per account + conversation (`src/chatgpt/queue/`), entered and edited only in ChatGPT's native composer: while a response runs, plain Enter appends with one blank line, there is no second input, no rows and no overflow menu. Waiting for the response or for Send is never an attempt and nothing is retried; a send claims an immutable in-flight snapshot. The Enter/submit/click interception lives only in `controller.js`; tests assert the card has no `textarea`/`input`.
- ResizeObserver is allowed only in `src/chatgpt/virtualization/backend.js` (active turn elements only); everything else observes through the hub.
- Startup is `src/core/boot.js`: it waits (one bounded observer, visible give-up) for the layout, restarts on route changes and root replacement, and a composer without turns (new chat) runs composer-only. Never add a one-shot layout check at script start.
- **One right-hand panel column** (#628, #969): `src/chatgpt/rail/rail.js` has ONE column pinned top-right: the conversation view (minimap) on top, the prompt list at the bottom growing up. ONE button in ChatGPT's header button area (`adapter.headerActions`, beside the outermost wrapper of the last native button; floating left of any pane that covers the header band) shows and hides both; the choice is remembered per browser by `createPanelPrefs` and both are shown by default. Never add a second button, a left panel, a card stack, fixed colors or a floating overlay on readable content; styling uses ChatGPT's tokens (`--color-surface-elevated-secondary`, `--elevation-prominent`, `--radius-2xl`, `--color-text*`, a test blocks literal colors). The minimap frame always fills its track at one fixed scale (conversation width / track width); a turn taller than the frame slides under it as the conversation scrolls, so its width never depends on the turn's length. A thread with no prompt of the owner's (a scheduled task's runs) lists each reply instead (`src/core/prompt-index.js`). The page-layout room is written only by `src/chatgpt/rail/rail-layout.js` (`data-gs-right` padding on the page column found by `adapter.columns`, which on a new chat is the widest composer ancestor that is not the whole window; our padding never changes the column's own box): it pads by exactly what the column takes so the conversation moves over (same width) and re-centers in the space left, hides again to the full centered width, is change-only and is removed on dispose; a native pane is classified by what it does under the padding (it moves with it, so it sits left of our column, or it stays, so our column sits left of it); with no room (below 1024px or under 560px of conversation) the column is a drawer opened by the button. Whatever ChatGPT's re-render removes (column, button, style) is put back by `rail.heal()`, which `core/boot.js` calls on every page mutation batch. ChatGPT's own summary pane is found structurally by `adapter.nativeSummary` (titles, regions, and ChatGPT's `data-summary-panel-*` hint), any other right-edge pane by `adapter.sidePane` (what is painted there); the summary pane is only ever given a disclosure on its Outputs section (`data-gs-*` attributes and one button; nothing native is moved, removed or re-created). Per-conversation panel state lives in `rail-state.js` (in memory) and `createPanePrefs` (the Outputs boolean, in `localStorage`) and never crosses conversation ids (tests/rail-layout.test.js, tests/native-pane.test.js, tests/right-column.test.js, tests/gate/rail.gate.js). The script never clicks the native summary toggle. `npm run visual` renders the built script on `tests/visual/mock-chatgpt.html` (synthetic text only) for screenshots; it is opt-in and not part of CI.
- The only automatic scroll is on opening a conversation: once the prompt list has settled the rail selects the last prompt like a click on it (`runtime.open` -> `scroll.mayOpen()`, its start at the top of the viewport), re-targets while more prompts keep loading, and stops for good when the list settles or on any user scroll, click, key or touch. All scroll writes go through `src/core/scroll-manager.js`; all DOM observation through `src/core/observers.js`; all ChatGPT selectors live in `src/chatgpt/adapter.js`.
- Public repository: no private data, profile paths, account names, tokens or personal identifiers anywhere (code, fixtures, commits, issues).
- Keep `@grant none` unless a review justifies a grant.
